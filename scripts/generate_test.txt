# =============================================================================
# conflict_vlm_v1 - dataset generation + cross-vendor eval commands
# =============================================================================
#
# WHY EVERY EVAL COMMAND PINS AN IMAGE SIZE
# -----------------------------------------
# The three max-image-edge flags have ASYMMETRIC defaults, so "no flag" does
# NOT mean "no resizing":
#
#     --anthropic-max-image-edge   default "auto"  -> sends originals
#     --gemini-max-image-edge      default high    -> sends originals
#     --openai-max-image-edge      default 1920    -> DOWNSCALES
#
# That silently handicapped every OpenAI run: measured on
# eval_results/data_3_5_flash (n=5509 images, R^2 >= 0.9997),
#
#     OpenAI  sent 1920x1080 (2.07 MP) -> 2042.6 tok/image
#     Claude  sent 3840x2160, server downscaled to 2576x1449 (3.73 MP)
#                                      -> 4786.6 tok/image
#     Gemini  sent 3840x2160, server resampled to a fixed token budget
#                                      -> 1100.6 tok/image
#
# i.e. OpenAI saw 55% of Claude's pixels purely because of a default nobody
# chose. Both numbers match the vendors' published patch formulas exactly:
#   Anthropic ceil(w/28)*ceil(h/28): 92*52   = 4784  (docs: "2576x1449, 4784")
#   OpenAI    ceil(w/32)*ceil(h/32): 60*34   = 2040
#
# ALIGNMENT TARGET = 2576 px long edge. That is Claude 4.7+'s own high-res
# ceiling, so it is the largest size all vendors will honour without a further
# server-side downscale. At 2576x1449 OpenAI costs 81*46 = 3726 tok/image
# (+83% vs 1920); images are ~81% of all prompt tokens, so budget ~1.67x on
# OpenAI runs.
#
# GEMINI IS DIFFERENT - RESIZING CANNOT ALIGN IT.
# Gemini resamples every image to a FIXED per-image token budget server-side,
# so --gemini-max-image-edge is a no-op for model-visible detail (8.29 MP and
# 1.08 MP both measured ~1100 tok). The only knob that changes what Gemini sees
# is --gemini-media-resolution: low=280, high=560, high=1120 (the default),
# ultra_high=2240 tok/image. We pin ultra_high to get Gemini as close to the
# other two as the API allows. The edge flag is still set, purely to cut
# upload bytes / latency.
#
# NOTE (Anthropic, >20 images per request): the vendor docs say requests with
# more than 20 image blocks get a stricter per-image dimension limit and
# recommend <= 2000 px. Some tasks here carry up to 23 images. Empirically this
# did not bite on Vertex (token cost stayed exactly 4784/image across 1-23
# images), but if you ever see an invalid_request_error mentioning
# "many-image requests", drop the Anthropic edge to 2000.

# other three on this dataset.
#
# ``_openai_reasoning_enabled()`` requires ``_openai_prefers_responses_api()``,
# which returns True only for provider ``bedrock-gpt`` or a model id starting
# with ``gpt-``. ``vertex-xai`` / ``grok-4.20-reasoning`` matches neither, so it
# falls back to Chat Completions - which has no encrypted-reasoning replay at
# all. Verified by constructing the agent: openai_reasoning=False,
# responses_api=False.
#
# Every other model here keeps its chain of thought continuous across the 20
# steps of an episode (Gemini thought_signature / Claude thinking blocks / GPT
# encrypted reasoning items). Grok would be the only one starting each step
# cold, which confounds any cross-vendor read.
#
